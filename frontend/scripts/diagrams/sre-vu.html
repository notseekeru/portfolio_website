what one virtual user does
28 requests · 1 interview · about 20 s
at 100 virtual users: 60-something requests a second, about 125 queries a second
identity · every virtual user is the same identity and they share one account: it is one candidate moving through the app, and the cleanup has one owner to delete. a real deployment gives accounts to users, many people at once.
stubs · the endpoints that carry generation are outside the run: NvidiaNIM for the model and Cloudflare Workers AI for voice both spend credit, so a vendor quota would fail the experiment. the model is stubbed and the voice path is off.
the run, in orderone virtual user, one interview
create
POST /api/interviews
a role, a topic, a level and the dials. nothing is authenticated in the perf window, so no token and no Clerk round trip. inserts one row and returns the interview, its id and the arc: nineteen questions for a standard run.
start
POST /interviews/{id}/start
one update to in_progress. every chat route refuses a run that is not in progress.
opener
POST /interviews/{id}/chat/opening
comes back as a stream. the server reads the interview, the resume attached to it and the whole transcript in one statement, then asks for a reply and stores it. in the perf window that reply is the stub, echoing the answer back word by word, no network and nothing billed. the client checks the last frame is done and keeps the text.
turns
POST /interviews/{id}/chat/send
two to eight of them drawn at random, one to three seconds of think time between each, so the shape looks like a person typing. on the server three statements: interview and transcript re-read in one, the credit and the message in one, the reply once the stub echoes it. four in production, where the tier lookup is not skipped. the transcript grows every turn, so turn six costs more than turn one.
finish
POST /interviews/{id}/finish
flips the status and runs the whole feedback pipeline inside the request: eleven statements, not a background job. the virtual user waits.
read back
GET /interviews/{id}/feedback
the feedback first, then the chat.
